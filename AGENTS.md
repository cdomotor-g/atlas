# Instructions for AI agents (Claude Code reads CLAUDE.md; this is the same text)

This repository is the **Atlas**: one map of all of cdomotor-g's repositories. It holds no
project code — only the map page, the collector that builds `data/map.json`, the
`atlas.json` format, and the drift check other repositories run. Read `README.md` first.

## What lives where
- `data/registry.json` — which repositories, where on the map, which zone. Edit to add one (`docs/adding-a-repo.md`).
- `data/fallback/<id>.json` — `atlas.json` for repositories that don't carry their own. Keep them true to the repository: read it before you change one.
- `data/map.json` — generated by `tools/collect.mjs`; never edit it by hand. The *Collect* workflow rewrites it every three hours and on pushes to `data/`, `tools/` or `schema/`.
- `schema/atlas.schema.json` — the format every repository's `atlas.json` follows. A change here is a change for every repository: keep it backwards compatible (add optional fields; never rename or remove one) unless the owner asks, and update `tools/lib.mjs`'s validator if you use a JSON Schema keyword it doesn't know.
- `tools/drift.mjs` and `.github/workflows/drift.yml` are called by every repository's `atlas.yml`. Breaking them breaks every repository's daily check.

## Checks before pushing
- `node test/check.mjs` — about a second, no network.
- A change to `index.html` or `assets/`: serve the folder (`python3 -m http.server`) and load it in headless Chromium (Playwright; `require('playwright')` works, never `playwright install`) at desktop and phone width, every view, with a repository and a link clicked: no page errors, no horizontal scroll.
- A change to `tools/`: run `node tools/collect.mjs` (in a cloud session prefix it with `NODE_USE_ENV_PROXY=1 NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt` so Node goes through the proxy) and look at what changed in `data/map.json`.

## Rules
- Public repository: nothing private goes in — no landholder details, site codes, secrets, private issue text. For private repositories the collector keeps counts, never titles or commit messages; keep it that way.
- Plain words in anything a person reads; give a word that means something particular here its meaning on hover (`title`), and list the meanings where a finger can read them too (the key, *How it works*).
- The Flood-Net app is **Flood-Net** in anything a person reads; its repository is `cdomotor-g/MegaNet`.
- Who clears what: `human` only for what needs my hands, money or say (hardware, a site, an order, a decision). What needs only my sign-in (a dashboard, a setting, an account page, GitHub settings) is `computer`: a Claude session at my computer does it signed in as me (Claude in Chrome for websites, computer use for apps, Claude Code through Remote Control for a shell) while I approve. Write blockers, options and issue tags that way (`[Human] [Computer]`), and keep the page's words saying the same.

## Git workflow
- Push straight to `main` after a patch. No pull requests, no branches unless asked. `git pull --rebase origin main` first: the *Collect* workflow commits `data/map.json` to `main` too.

## Run summary — how to end a run
When you finish a piece of work, end your reply with this report, filled in. A short reply that only answers a question (no work done) skips it and doesn't use up a run number.

```markdown
---
# 🏁 THIS RUN SUMMARY (Run N)
> **You asked:** what I asked for, in a few words.
>
> What this run achieved, in one plain sentence. **Needs you:** Y1, Q1 — or **Nothing needs you.**

## ✅ Done
- **D1** What changed and where, with a link when there is one (commit, issue, page).

## 🧪 Checks
- **C1** 🟢 What was checked, and what it showed.

## 🚧 Not done
- **N1** What was skipped, failed or is left for later, and why.

## 🙋 Needs you
- **Y1** What needs your hands, money or say, step by step.

## 💻 Needs your sign-in
- **S1** What needs only your sign-in, as a brief to paste into Dispatch.

## ❓ Questions
- **Q1** The question. Options as **Q1.1**, **Q1.2**, the one you'd pick marked *(recommended)*.
```

- **The marker.** A horizontal rule, then the 🏁 heading word for word, so I can find it by scrolling. N counts the summaries in this chat: Run 1 first, then one more than the last marker. A new chat starts at Run 1. Use it once per reply, at the start of the report: everything above it is working notes, and nothing comes after the report.
- **What I asked, then what came of it.** Straight under the heading, **You asked:** and my request in ten words at most (several asks joined with ·), so I can tell which request a report answers when I scroll back. Then one plain sentence on what the run achieved, listing every Y, S and Q point, or saying nothing needs me.
- **Same sections, same letters, every repository.** These headings, emoji and order; leave out any that would be empty, and add none. Every point starts with its section's letter and number: **D** done · **C** checks · **N** not done · **Y** needs you · **S** needs your sign-in · **Q** questions. Nest with a dot (**D2.1**). Numbers restart each run, so when I reply "Q1: yes" or "Run 2 Y1", that's the point I mean.
- **Checks show their result:** 🟢 passed · 🟡 passed with a warning · 🔴 failed · ⚪ not run, and why. Never call something fixed or passing that wasn't checked.
- **Needs you, or needs your sign-in.** **Y** is only what needs my hands, money or say: hardware, a site, an order, a decision. What needs only my sign-in (a dashboard, a setting, an account page) is **S**: do it yourself if this session can use my computer; otherwise write it as a brief I can paste into Dispatch.
- **Short.** One line a point, two at most: what happened and what it means for me, not how it was done.
- **Plain words.** I'm not a software engineer, and I may read only this report. Prefer the everyday word. Where a technical term, an abbreviation, a word used in a special sense, or a mention of something I may not have seen (a file, a tool, an earlier step) is the clearest choice, add a few words saying what it is the first time. Name a thing by what it does, not only by its file or function name.
