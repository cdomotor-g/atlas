# Instructions for AI agents (Claude Code reads CLAUDE.md; this is the same text)

This repository is the **Atlas**: one map of all of cdomotor-g's repositories. It holds no
project code — only the map page, the collector that builds `data/map.json`, the
`atlas.json` format, and the drift check other repositories run. Read `README.md` first.

## What lives where
- `data/registry.json` — which repositories, where on the map, which zone. Edit to add one (`docs/adding-a-repo.md`).
- `data/fallback/<id>.json` — `atlas.json` for repositories that don't carry their own. Keep them true to the repository: read it before you change one.
- `assets/triage.js` — the Priorities view's sums (importance, cost, a plan in time); `docs/priorities.md` says how it weighs, in words. An issue says how it weighs with an `Atlas triage:` line (`triageMark` in `tools/lib.mjs`); repository `weight`s and the `triage` settings live in `data/registry.json`. Change the sums and the words together, and keep `test/check.mjs`'s cases passing.
- `data/map.json` — generated by `tools/collect.mjs`; never edit it by hand. The *Collect* workflow rewrites it every three hours and on pushes to `data/`, `tools/` or `schema/`.
- `schema/atlas.schema.json` — the format every repository's `atlas.json` follows. A change here is a change for every repository: keep it backwards compatible (add optional fields; never rename or remove one) unless the owner asks, and update `tools/lib.mjs`'s validator if you use a JSON Schema keyword it doesn't know.
- `tools/drift.mjs` and `.github/workflows/drift.yml` are called by every repository's `atlas.yml`. Breaking them breaks every repository's daily check.
- `shared/instructions.md` — the rules every one of the owner's repositories shares (pushing, plain words, private data, who clears what, issue titles, the run summary); `shared/on-the-atlas.md` — the extra rules for repositories with an `atlas.json`. Every session in every repository downloads them when it starts, so a change here changes how every agent works, from its next session. Each must stay under 9,500 characters (a start-up hook hands the agent at most 10,000). `docs/shared-instructions.md` explains how it works; `node tools/shared.mjs <repository folder>` points a repository at them.

## Checks before pushing
- `node test/check.mjs` — about a second, no network.
- A change to `index.html` or `assets/`: serve the folder (`python3 -m http.server`) and load it in headless Chromium (Playwright; `require('playwright')` works, never `playwright install`) at desktop and phone width, every view, with a repository and a link clicked: no page errors, no horizontal scroll.
- A change to `tools/`: run `node tools/collect.mjs` (in a cloud session prefix it with `NODE_USE_ENV_PROXY=1 NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt` so Node goes through the proxy) and look at what changed in `data/map.json`.

## Rules
- For private repositories the collector keeps counts, never titles or commit messages; keep it that way.
- The page's words say what the shared instructions say — who clears what, plain words with a meaning on hover (`title`) and the same meanings where a finger can read them (the key, *How it works*).
